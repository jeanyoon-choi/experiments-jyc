# HTTPS and sockets

[AGENTS.md](../../AGENTS.md) owns agent execution restrictions and exact
server-request wording. The following commands describe user-operated setup.

`pnpm dev` starts HTTPS apps on SCC 2000, Goldfishes 2001, six-sigma 2002,
xyt-cube 2003, ddong-meong 2010, C-VAL 2011, and Socket.IO 4000.
`pnpm dev:scc`, `dev:c-val`, `dev:ddong-meong`, `dev:goldfishes`, or
`dev:six-sigma`, or `dev:xyt-cube` starts one app plus relay.
The runner preflights selected ports before launch.

Port overrides: `SCC_PORT`, `C_VAL_PORT`, `DDONG_MEONG_PORT`,
`GOLDFISHES_PORT`, `SIX_SIGMA_PORT`, `XYT_CUBE_PORT`, and `SOCKET_PORT`/`NEXT_PUBLIC_SOCKET_PORT`.
Clients use configured `NEXT_PUBLIC_SOCKET_URL`, otherwise the HTTPS hostname
and socket port. The root CA is served by the relay at `/cert`.

Certificates are generated by `scripts/generate-certs.sh`, stored in
git-ignored `certificates/`; orchestration lives in `scripts/dev-https.mjs`
and `socket/create-socket-server.mjs`.

App handlers belong in `apps/<owner>/socket/experiments/`.
`socket-server.mjs` loads complete or scoped registries, not artwork state.
Each experiment has isolated events, rooms, and state. Handlers own abstract
state, parameters, flows, interventions, histories, and time; browsers own all
visual mappings. Goldfishes registers versioned protocols (`goldfishes-feed:1`,
[contract](../../apps/goldfishes/docs/socket/feed/1.md)); handlers must not
borrow another artwork's namespace.

Production is a separate stateful service:
[shared relay runbook](scc-relay-deployment.md).
