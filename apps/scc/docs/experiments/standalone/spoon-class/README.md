# spoon-class

`/spoon-class/default` embeds one actual `dino.html` from [alexelzx/chrome-dino](https://github.com/alexelzx/chrome-dino), pinned to commit `6e472666cfd94e95056b7e747f46badf00e1226d`. `/spoon-class/1` is the responsive module-field fork. `/spoon-class/2` is its human-life visual fork: a pixel human begins at age `0`, low obstacles are tests, and tall obstacles are larger life blocks. `/spoon-class/2` also carries the former high-density wall as its `dense` option. `/spoon-class/3` (2026-10-03) is the mobile stack: its own copy of the `2` source, one full-width game per row, eight rows by default. `/spoon-class/4` (2026-10-26) is the race: eight runners, one per row, all on one screen. `/spoon-class` lists all variants.

## Baseline and ownership

The editable upstream HTML is stored byte-for-byte in `components/standalone/spoon-class/default/source/dino.html`, `1/source/dino.html` and `2/source/dino.html`. It includes the complete Runner, Trex, Horizon, Obstacle, DistanceMeter and GameOverPanel implementations, both sets of seven PNG sprites, three encoded sounds, and original document/CSS. Jump physics, rounding, spawn rules, collision boxes, sound decoding, score flashing, and restart exceptions execute unchanged. The intro completion bridge and the browser correction are the explicit compatibility corrections described below. Do not replace the engine with redrawn shapes, synthesized audio, rewritten physics, or constants from another Dino release.

The `default`, `1` and `2` `source/package-source.mjs` scripts package the HTML as `source/document.json` for a static import and add a Content Security Policy to disable external requests plus `compatibility.mjs` before the original bootstrap. `default` changes only the upper-right HUD into the age clock. `1` additionally sets a 150px tile viewport, removes the original prompt/share/non-Chrome notice DOM, and relays trusted player key events to its wall host. `2` retains that module surface and input relay, but replaces only the six Runner image resources for both pixel densities: T-Rex frames become a human, small cactus frames become test papers, and large cactus frames become life blocks. `3` has its own copy of the `2` source and packaging. The bridge listens for standard `animationend` and completes the original 400ms intro by timer when no event arrives. Completion is idempotent so a late event cannot reset the runway or duplicate listeners. The original engine freezes world time while `playingIntro` is true; missing completion otherwise leaves cacti stationary indefinitely. The Runner engine, source styles and embedded media stay intact. Regenerate the matching variant with `node apps/scc/components/standalone/spoon-class/<variant>/source/package-source.mjs` after an intentional source change and document that change.

`default` renders one viewport-sized source iframe. `1` and `2` measure their own viewport, repeat only the needed number of 150px-high tiles, and remeasure on resize. `3` shows eight rows by default, scales each native 150px-high document to one fixed size per screen (the default eight-row fill), and widens the document by the inverse scale so the runway spans the full row; Runner lays out its world at that width, slowing only below its own 600px threshold as upstream does on small screens. Rows always divide the screen, but the row count never resizes text, character or runway: a taller row centres its game, and a shorter row crops the game instead, first up to 8 document pixels of empty ground margin, then sky from the top, with the age clock (drawn at 1.5× in `3`) moved down by the cropped sky through `window.spoonClassClockTop`. On very wide, short screens the runway never narrows below 480 document pixels. A play button (ink disc, rounded light triangle) starts every row with one Space press and returns whenever rows or resolution change. The bottom-right `옵션` control (finger-network pattern) holds a row stepper (1–10, eight first), a resolution choice (`자동`, `1x`, `2x`, `3x`) and `성능`, a readout of host frame rate, mean and worst frame time, game count and pixel ratio; same-origin game documents share the host main thread, so host cadence measures the whole stack. `자동` sets each game's `devicePixelRatio` to screen ratio × row scale, capped at 2, through a script injected before the engine; drawing at the full 3× of a phone filled 2.25× the displayed pixels in every game every frame, and dropped frames make Runner's time-based motion jump. The age clock now clears the full 2y..2y+13 band of the source digits drawn before the first update (the source translates by y and then draws at y again), removing a residue under the clock on the start screen in `default`, `2` and `3`. In `2`, the bottom-right `옵션` control (the finger-network toggle pattern: `옵션`/`닫기`, pressed option at full opacity) switches between `less dense`, the default 150px-tile field, and `dense`. Each switch starts a fresh set of games. `dense` keeps each source document at its native 600×150 canvas size, then scales the complete browsing context inside each tile: it selects 4×10 at normal desktop density, reaches 6×15 only when each game can remain at least 50% scale, and reduces the count on small displays before game pixels fall below 32% scale. Each source document has script and same-origin permissions, retaining normal document-origin semantics for the local trusted source. It preserves quirks mode, default browser styles, style-sheet indexing, global singleton, event targets and canvas coordinates independently of SCC's Tailwind reset. In all module variants, Space, Up, Down and Enter are forwarded from the host or any focused game tile to every game tile; their original Runner listeners perform the response. In `default`, `2` and `3`, the upper-right score is replaced by the pixel age clock `00Y 00M 00D`; it starts at birth and advances six months every second, with a 30-day interpolation within each month. `MONTHS_PER_SECOND` is the sole setting for future pacing changes. Removing a tile destroys its game document and its listeners, animation loop and audio context. The route and experiment registry remain thin. No dependencies or servers are added.

2026-10-03 browser correction: the upstream bootstrap constructed the Runner only for user agents containing `chrome`, so Safari, Firefox and every iOS browser (iOS Chrome reports `CriOS`) showed no game, and touch input was enabled only for `Mobi` user agents, so iPadOS and Android tablets could not tap to jump. Each variant's `source/browser.mjs` lists three exact upstream lines and their packaged replacements: the game always starts, the trailing guard always matches Chrome's presentation, and `IS_MOBILE` also covers coarse-pointer touch devices. The same module adds a gesture style (no double-tap zoom, long-press selection or tap flash) and an audio adapter (`webkitAudioContext` fallback; a failed Ogg decode in Safari stays silent). In `1`, `2` and `3`, a touch in any tile is relayed as one Space press to every tile, matching the host keyboard path. The wall height falls back to `100vh` where `svh` is unsupported. `dino.html` stays byte-identical; tests restore the packaged document to it.

2026-10-03 sound: the upstream page carries three Ogg Vorbis sounds (press, hit, score). In `1`, `2` and `3` each module's own audio context stayed suspended, because only the frame that receives a gesture may start audio and the wall relays input as synthetic events, so the modules were silent. Their packaged module script now routes `Runner.prototype.playSound` to the host as a `spoon-class-sound` message (`loadSounds` records sound names instead of decoding per frame). `game-audio.ts` decodes the three embedded sounds once in a single host context and plays each module's sound as its own voice, so simultaneous games overlap; per-voice gain is 1/√(game count) into a compressor, voices are capped at 24. Any trusted touch, click or key in the host or a module calls `spoonClassUnlockAudio` synchronously, retrying until the context runs (touch grants permission only on release), and sounds sent during the unlocking press wait for that resume. Browsers that cannot decode Ogg Vorbis stay silent. In `3`, a cropped row also lowers the jump apex below the cropped sky (`jump-ceiling.mjs`): the source jump is replayed at 60fps steps and the smallest change is chosen, raising `MAX_JUMP_HEIGHT` first and reducing take-off velocity only when that is exhausted; gravity, drop velocity, ground and collision boxes are unchanged.

2026-10-26 books in `3`: the `옵션` panel's first row chooses `책` (default: the original tests and life blocks) or `문제집`; switching starts fresh games, as the other options do. With `문제집`, both obstacle sprites are shelves of real workbook spines standing upright at full obstacle height, drawn 2.2× thicker than photographed so titles read at game size, in a random order per game — 수학의 정석 (twice as likely) with 쎈, 개념원리, 블랙라벨, 자이스토리 and 마플 시너지. The spines are Aladin's spine downloads (e.g. [실력 수학의 정석 대수](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=350843530), [쎈 공통수학1](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=359950633)), reduced to 200px high in `3/source/books/` and packaged as data URIs and passed into `installLifeGamePresentation` when the host sets `window.spoonClassWorkbooks`. Only the six sprite images change; obstacle types, sizes, gaps and collision boxes stay the source's, so the human jumps the same game. Without books the function keeps the earlier test and life-block sprites.

2026-10-26 options sheet and lifespan order in `3`: the bottom-right `옵션` is now an outlined pill that opens an opaque sheet above the games (labelled rows `장애물`, `성장`, `정렬`, `해상도`, `줄`, `성능`; the chosen value inverted), because the bare text controls disappeared against the rows. `정렬` chooses `그대로` (default, rows fixed) or `수명순`. In `수명순` the order changes only when a game ends (the host checks every 200ms for a new crash through each game's `Runner.instance_.crashed`). Lives are then ranked by whole years lived, read from the age clock exposed as `window.spoonClassAge` by `life-age.mjs` (it stops at a crash and returns to 0 on restart); one year is 2s, a running game counts its years so far, and equal years keep their order, so only a meaningful difference moves a row. Rows move by `transform` over 360ms, never in the DOM, since moving an iframe reloads its game.

2026-10-26 growth in `3` (`성장`, default `켬`): `growth.mjs` grows the human with the age clock, from the /3 baby (44×47) at birth to a grown body (54×78) at 18 years: taller, longer legs set wider apart, a scaled crashed pose. On each height step it swaps a regenerated sprite sheet (after it loads), rescales the private animation frame lists in place, and moves the ground position so the feet stay on the ground. The source's collision boxes are deliberately left alone: they keep covering the top 47 pixels of the body (head and torso), so whatever passes below them goes between the legs and a grown runner clears books with a lower jump. Gravity, jump velocities, speed and obstacles are unchanged. A restart returns to the baby. `끔` keeps the earlier /3 baby throughout.

## Source and evidence

The upstream GPL-2.0 `LICENSE` is retained alongside the source, together with the Chromium copyright/BSD notices already embedded in the HTML. Preserve both. The [freeCodeCamp article](https://www.freecodecamp.org/news/how-the-chrome-dino-game-works/) is background reading; the pinned source defines this experiment's actual behavior.

2026-09-08 correction: the earlier hand-drawn renderer, synthesized cues and rewritten model were rejected for failing source fidelity and removed from this variant. The baseline is now the upstream game itself; the intervention is its isolated SCC host and restriction of unrelated external requests. Future experiments should fork this baseline into a new registered variant.

2026-09-08 verification: all 26 source tests (`default`: 8, `1`: 8, `2`: 10), scoped ESLint and the full SCC typecheck passed. The tests cover upstream byte comparison, packaged-source equality, inline JavaScript parsing, embedded asset integrity, the stationary-cactus failure when intro completion is withheld, fallback completion, differential runs against the unmodified source, the synchronized input relay, `2`'s six sprite substitutions and the shared six-month age clock.

Follow-up after the user reported stationary cacti: the original engine reproduced that state in a controlled Node clock when the animation completion event was withheld. With a matching source intro-end event, the hosted engine and the unmodified source were state-identical over 900 frames, including current speed, cumulative distance, T-Rex jump state, horizon offset, cloud state, obstacle type/size/position/gap/collision boxes, score flash, collision, restart and post-restart movement. The compatibility bridge also completed the original intro when no event arrived, then moved cacti toward the player. Duplicate completion did not reset the runway. Browser verification at the supplied local HTTPS route confirmed that `default` is one original game, `1` fills the viewport with modules, and host Space starts every visible module. `2` visibly renders the human, test and large-life-obstacle sprites; Space makes every visible human jump. Touch and audio paths remain unverified.

## /4 race

`4` has no game documents: `race.ts` advances eight upstream Runner worlds in one simulation (speed, acceleration, jump, speed drop, gaps, clouds, ground bumps and collision rules from the pinned `dino.html`), and `render.ts` draws the rows into one canvas. `source/package-source.mjs` copies the upstream ground, cloud, press and hit resources byte for byte into `source/assets.json`. One tap (or Space/Up) jumps every runner; obstacles differ per row, so the same effort meets different luck.

Every obstacle is a row of 수학의 정석: 3, 5 or 7 books (upstream sizes 1–3) standing upright side by side, spines out, 50 high and 5.2 thick (the photograph's 104×1000 proportion). The spine is a real photograph, Aladin's spine download for 「실력 수학의 정석 대수」 (성지출판, [item 350843530](https://www.aladin.co.kr/shop/wproduct.aspx?ItemId=350843530)), stored as `source/math-spine.jpg`; 기본 editions are the same image hue-shifted to orange. A row of books collides as one block. The runner collides by the `3` human's own outline (head, torso with arms, legs) instead of the T-rex boxes, and every obstacle is checked, not only the first as upstream: a runner standing right of x=50 otherwise met the next obstacle unchecked while the one it had passed was still on screen.

A hit never ends a run: the runner lies down shaking under a `아야!` bubble while its world stands still for `STUN_DURATION` (1s), then gets up and blinks while passing through the obstacle it hit. Horizontal place follows rank, recomputed every frame: the middle rank at the middle of the row, first at the right, last at the left (x=8), evenly between; tied runners share the mean of their ranks, so a field without hits stands in the middle. Runners walk to a new place gradually (600ms time constant) and stay where they fell while hurt. Obstacles first appear as far ahead of each runner as upstream (from x=50), off the right edge for runners further right. Every runner keeps its own row; only its horizontal place changes. Each row shows a fixed Korean name at top left and the age clock at top right. `옵션` holds `다시` and `성능`. `source/race.test.mjs` covers asset identity, the one-second stall and runners keeping their rows while placed by distance.

## Direction: life-stage obstacles (2026-10-26, not yet built)

The user's long-term intent for `4`. Today the row of 수학의 정석 is the large obstacle at every age. It stands for one stage — 입시 — of a larger sequence.

- The obstacles should follow the age clock: what each runner must jump over is the task Korean society says belongs to that age. Earlier ages have their own tasks before 입시; in the twenties, a good university, a good job and a good marriage; then childcare, promotion, retirement and preparing for old age.
- The end is a hospital, and hospitals differ in grade too (the plausible private room). The race keeps ranking to the last stage.
- The meaning: an endless competition with a fixed timetable, ranked at every step, that ends the same for everyone. The ranking is real inside the race and meaningless at its end. The reference is 허준이's 2022 Seoul National University commencement address ([중앙일보](https://www.joongang.co.kr/article/25097908)): his wish that graduates not be distracted by "preparation" for jobs, marriage, childcare, promotion, retirement and old age, and finally for dying in a plausible private hospital room.
- Build it as stage obstacles selected by age, collaged from real images like the 수학의 정석 spine, keeping obstacle sizes and collision boxes. The stage boundaries by age are not decided yet; ask before fixing them.
