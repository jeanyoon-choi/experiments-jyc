# Splice: learning to perform a collage

Design interpretation, 2026-09-16. This records the user's new direction and the reason for the first audio instrument. It is a proposition to try, not a claim that the resulting experience has been observed or accepted.

## The material is the running computer

The requested long-term work operates inside the actual computer: real browsers, tabs, programs, terminals, conversations, loading processes and competing agents. Opening, foregrounding, scrolling, revisiting and closing change that computer's state. The interface collage takes place through these changes. A Slack window has its own unread state; a browser tab may still be loading when another action covers it; returning to a conversation does not return the world to the moment it was left. Those independent continuities are material to the work.

This is the consequential correction to the rejected Goldfishes browser print trial (since removed). That trial flattened authored interface fragments into a canvas. It could compose the appearance of attention pressure, but the fragments did not retain application behavior. The existing [native desktop trial](../../../../../goldfishes/components/native-windows/docs/3.md) is closer: it tracks actual Chrome tabs, makes new ones, revisits surviving ones and lets Terminal interrupt. Its decisions are scripted probabilities. Its own documentation correctly does not call them reasoning agents.

The user's affirmation of chaos and error should survive this distinction. A delayed command, an unexpected page or an agent's bad choice can alter the next action and remain in the performance. They need not be concealed or converted into a predetermined visual glitch. A future controller can expose actual outcomes to the agents and let them respond. At present, that is an architectural direction; this audio instrument neither operates applications nor contains AI agents.

## What audio makes available to the hands

The useful starting point in the DJ reference is an operation on existing time. A track already has duration, timbre, phrasing and expectations. Choosing an entry point changes which part of that history is heard. Repeating a fragment establishes an expectation. Cutting away makes its absence audible. Bringing it back changes the meaning of the intervening sound. The listener experiences a relationship between sources, even when neither source was composed for that relationship.

Splice puts two independent sounds under the hands so these actions can be learned by doing. Four hot cues on each deck let selected moments recur. A loop changes the scale of attention from a complete phrase to a small event. Halving the loop repeatedly can make a recognizable phrase become a pulse or texture. Speed couples duration and pitch. A filter changes which frequencies of a source occupy the mix. A crossfader supplies both continuous overlap and sudden exclusion. A recording retains decisions as audible time rather than as a final arrangement of controls.

These are ordinary DJ operations, with their operational meanings checked against the [Mixxx manual](https://manual.mixxx.org/2.5/en/chapters/user_interface). Splice is deliberately a small practice instrument: it does not claim Mixxx's beat analysis, pitch-preserving time stretching, headphone routing or controller integration. The Daft Punk reference motivates attention to selection, transformation and recurrence; it supplies neither sampled recordings nor a claim to reproduce their production process.

Two decks are a useful initial constraint because you can hear what each intervention does to the relation. This is not a requirement that the later computer work remain orderly or limited to two sources. After the gestures become familiar, additional simultaneous sources and independent decision makers can make the outcome less knowable without removing the ability to act within it.

## What transfers, and what changes

| Audio action | Possible native operation | Difference that must remain real |
| --- | --- | --- |
| Load a source | Open an actual app, tab or document | The source may take time to become usable and continues evolving. |
| Recall a hot cue | Revisit an identified tab, app state or actionable location | Foregrounding a source does not rewind it. |
| Loop a fragment | Repeat a gesture or revisit a bounded group of sources | Repetition acts on a changing system; repeated actions may have different results. |
| Change speed | Change the rate at which actions are requested | Requested cadence can exceed application response time. Queueing and dropped actions affect the result. |
| Crossfade / cut | Change foreground, visible area, occlusion or dwell time | Visual attention is not an equal-power audio equation, and occluded apps can keep running. |
| Silence | Leave an interval without a new action | The computer may still contain motion, notifications and processes. |
| Record a take | Capture the screen plus a timestamped action/outcome record | A video retains what appeared; the outcome record explains which actions completed, failed or were superseded. |

This mapping is a design analogy, not an empirical account of attention. It argues for carrying over the action vocabulary while writing a native execution layer that respects application identity and asynchronous outcomes. Audio samples permit precise clocked looping. Native apps provide resistance, latency and histories that cannot be sampled away without returning to a simulation.

The first native extension should therefore make a small set of actual window/tab operations playable and record their outcomes. The existing native runner is a local precedent for ownership and revisits. A subsequent experiment could let multiple agents observe those outcomes and make independent proposals; their collisions, errors and interruptions would then arise from actual decisions. No agent execution framework is being smuggled into this audio version, and no simulated activity is presented as an agent decision.

## A first practice

Load the practice pair and play both. Listen at the center, then cut to A and back to B. On B, choose a moment and set a hot cue. Set a loop around part of the phrase and halve it until its original shape changes. Move the filter while A continues. Turn the loop off and recall the cue. Record one minute in which a recognizable fragment repeatedly returns, but each return meets a different interval, speed or overlap. Then try the same actions with two unrelated personal recordings.

The open question is whether this builds a bodily sense of selection, duration and interruption that the later native system can preserve while other agents act. Passing static checks does not answer that question. Listening, playing and eventually encountering the agents' actual actions must do so.
