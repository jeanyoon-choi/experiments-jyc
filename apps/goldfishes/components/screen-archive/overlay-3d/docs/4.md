## Bubble-scale trial — 2026-09-13

### Runtime population and attention controls — 2026-09-16

The control panel can now set an approximate level for **simultaneously active bubbles** without changing the underlying grid or social-tie topology. `natural level` is the default and preserves the previous behavior exactly. Moving the `active` slider supplies a population target for all non-empty states (`new`, `viewing`, and `leaving`), not a fixed count or hard maximum. Below the target, external arrivals replenish the field and successful propagation events are admitted normally; near the target, a separate outer admission gate tapers only the creation of propagated bubbles; above it, existing bubbles finish their normal lifecycle. The population therefore continues to fluctuate around the requested level. Original attention-driven transmission probability, tie selection, state lifetimes, adaptive attention extension, random sequence, and fish behavior are untouched in the default `natural` mode.

`speed` changes the complete bubble-system clock from 0.1× to 2× in 0.1 increments. At higher values the same fixed simulation step is scheduled more frequently; at lower values it is scheduled less frequently. Consequently external arrivals, first and repeated transmissions, `new` visibility, viewing, leaving and cooldown transitions all retain their original simulation-time constants but run faster or slower in real time. CSS entry, exit, viewing-ring and influence-trace durations use the inverse of the same multiplier, so rendered motion remains synchronized with state transitions. Transmission probability, tie selection, number of transmissions per story, local weights, attention equations and per-step propagation safety limit are not rewritten. The default is 1×.

`pause` freezes the story-system clock, propagation and replenishment while leaving the goldfish school alive; `play` resumes from the same simulation time without catch-up. Contact accumulated during a pause is discarded so resuming cannot produce a deferred attention spike. Active CSS entry, viewing-ring and influence animations use `animation-play-state: paused` with the same control. The default is playing.

`attention cap` is a separate, optional hard ceiling on how many fish may be assigned to any one active bubble. It is off by default, so the previous soft crowd penalty remains the sole distribution mechanism. When enabled, the default ceiling is 80 fish per bubble and is adjustable from 1–600. Existing target assignments are reconsidered immediately; candidate bubbles at capacity are excluded, while the original distance, novelty, loyalty, affinity, familiarity and local crowd scoring remains unchanged for candidates below the cap. Fish that cannot find a nearby target with capacity remain untargeted and continue the existing traffic-following behavior.

`story rings > colour` includes a `Transparent` option. It removes the circular story border—including the otherwise per-keyword Tech ring—without hiding the separate propagation trace; its checkerboard control swatch is only an interface indication of transparency.

The leaving state retains the viewed ring's padding and separator geometry until the bubble is fully transparent. Previously, entering `leaving` incorrectly selected the `plain` ring class, which removed both inset and separator while still visible: the inner image expanded abruptly and was then reduced by the parent exit scale. Only the ring paint now fades at that transition; geometry changes after the invisible `empty` state.

Empty nodes now use an invisible `dormant` ring that retains the same padding and separator geometry as an active node. This specifically removes the inverse inner resize previously exposed by propagated arrivals: `empty/plain → new` used to animate padding and border from zero while the parent pop-in enlarged, making the image contract as the bubble expanded. External and propagated arrivals now share one continuous opacity/scale entrance without altering propagation or per-occurrence scale selection. The fish-size control extends down to 0.7×; its existing 0.8× default is unchanged.

Each story appearance receives one deterministic scale in the inclusive 0.5–1.5 range (mean 1.0, so the former 50px default remains the average). Its `new`, `viewing`, and `leaving` lifetimes use the same multiplier. The baseline appearing and disappearing controls are both 0.30 seconds. Appearance duration is deliberately independent of the random bubble scale: every external or propagated arrival enters over the same base time, from 72% of its assigned final size to 100%, instead of small bubbles completing a nearly imperceptible 92%→100% motion in as little as 0.15 seconds. The model also prevents every `new → viewing` transition until the full configured appearance interval has elapsed from that occurrence's `availableAt`; this is essential for propagated bubbles whose former `1.2s × bubbleScale` new lifetime could otherwise cancel a longer entry animation midway and snap to its final frame. Disappearance remains proportional to bubble scale, producing 0.15–0.45 seconds at the default control value; the separate viewing-ring duration remains 0.76 seconds at scale 1. `bubble animation` controls adjust appearing duration from 0.05–1.20 seconds and disappearing duration from 0.05–2.00 seconds. Activity speed divides the rendered durations consistently. The disappearing value controls both the CSS fade/scale transition and the simulation's `leaving` state lifetime, while the appearing value controls both the CSS entry and its minimum `new` state residence. The grid slots, surface treatment, story propagation, and goldfish force coefficients remain fixed. The school now reads each bubble's rendered radius for approach, contact, target rings, and obstacle resolution, so a fish is kept clear of the actual circle edge while longer-lived, larger bubbles remain available to attract it.

The reduced-motion media query no longer overrides `.story` animation duration with `0.01ms`. That cascade previously made the explicit `appear` and `disappear` controls ineffective whenever the host reported `prefers-reduced-motion: reduce`, most visibly on recurrent propagated arrivals. User-selected bubble timing is now authoritative; reduced-motion handling remains on the ring, logo, influence and panel effects.

Browser measurement exposed a second perceptual timing fault: the entry used one strongly front-loaded `cubic-bezier(0.2, 0.85, 0.3, 1)` for both opacity and scale, so even a configured 0.90-second appearance reached most of its opacity in the first few tenths and spent the remaining duration nearly static. Entry opacity now progresses linearly across the full selected interval, while scale uses a separate restrained ease-in/out curve. The control therefore governs the full visible emergence rather than only a long imperceptible animation tail.

The `line` slider in `bubble system` multiplies propagation-line opacity from 0 to 1 in 0.05 increments without changing transmission state or timing; its default is 1. The trace keeps its independent 1.2-second animation rather than using the bubble `appear` and `disappear` controls.

The surface controls also include `hieroglyphs`, with right-side `default` / `tech` selection. Default preserves the Egyptian-hieroglyph sequence used by LinkedIn/4. Tech contains 36 original SVG compositions using profile figures, seated/kneeling poses, hands and subordinate technology signs. These are invented contemporary signs, not historical translations. The rejected modern icon paths were replaced; generated raster trials are not used. SVG ink bounds determine horizontal and vertical centering at every bubble size. Visual review covered the 36-sign SVG contact sheet; stylistic acceptance remains with the user.

The default surface is `eyes`, with `big tech colour` selected by default. The surface contains three internal types. `human` preserves the 75 existing photographic human-eye collage assets unchanged. `big tech` reuses the 80-person technology-power sequence but shows a single eye cropped from each portrait. `big tech colour` applies the same person-to-company/service palette used by `face > big tech colour` to those eye crops. The crops are generated locally with macOS Vision face landmarks by `source/crop-tech-power-eyes.swift`; each crop is a derived fragment of its corresponding attributed Wikimedia portrait rather than a new external source. Keeping these under `eyes`, rather than `face`, makes the selectable category follow the perceived unit (one eye versus a whole face). Existing appearance timing, per-occurrence scale, rings, propagation and fish-target geometry remain unchanged.

The `lips` surface separates source, crop and colour into three independently combinable axes. `lip source` selects the 80-person technology set, the 60-person politician set, or a balanced alternating `tech + politician` sequence. `lip version` switches between `lips-v1`, the square crop that retains some surrounding mouth context, and `lips-v2`, a tight outer-lip crop whose wide source is enlarged with `cover` so the lips fill the story circle. `lip colour` selects `original`, source-specific colour, or `red`. Source-specific colour applies company/service palettes to Tech people and the established red/blue political palette to politicians, including inside the mixed sequence. `red` does not flatten the whole crop: separate translucent crimson and rose soft-light fields target the upper and lower lip zones, leave the central mouth/teeth less affected, and add a restrained highlight while retaining photographic texture. ## Implementation contract

- `model/approach-events.ts`: selected-target entry at radius +24 CSS px, independent of visible rings; 4px hysteresis / 0.8s per-fish cooldown; silent initial priming. Existing detector supports IDs 0–999.
- `audio/approach-samples.ts`: one fetch/decode; up to 32 short 240–290ms fragments. Remove DC, bound normalization, skip high-crest isolated impacts; 25ms raised-cosine entrance / 75ms exit soften cuts. These are mechanical selections, not individually auditioned editorial choices.
- `audio/approach-sound.ts`: cycle the same source material at original pitch/speed. Approach speed changes level; target position gives narrow stereo placement; dense entries attenuate. No note bank, extra effects, continuous water loop or synthesized fallback.
- Eight fixed gain/panner slots and master/compressor; at most eight transient buffer sources, disconnected on completion. 75ms global / 160ms per-target admission gaps; overload omitted, never queued. Unlike former oscillator pooling, this allocates one short-lived source per admitted event; memory is bounded but actual browser cost is unmeasured.
- Default OFF / volume 35; only explicit activation initializes audio and loads samples. Hidden tab suspends; explicit OFF is respected; unmount aborts fetch, stops sources and closes context. Failed loading reports an error instead of substituting a rejected beep.
