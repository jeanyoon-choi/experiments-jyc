# PC / 0908 / variations

`/pc/news-phones/2`: a standalone copy of the default phone field. The bottom switch selects flat `colours`, a large technology `keywords` surface, `keyword + sentence`, or `google`; a local template ID and surface index choose the text variant. Surfaces advance only while invisible. Count, rows, size, margin, presence, and speed remain testable.

The `google` option tests whether a repeated mobile-search grammar makes the field legible as a collection of active information surfaces. Its baseline is the existing keyword surface; the change is a local mobile results frame—wordmark, search field, result-type tabs, and result list—while phone geometry, timing, and controls remain unchanged. Every phone uses its existing keyword index as a query and stable local `.example` result data; it makes no Google request and does not represent live or personalized search results. The public Android Search help confirms the mobile search-field → results-type filter sequence, while the exact set and order of filters remains query-dependent: [Google Search Help](https://support.google.com/websearch/answer/142143?co=GENIE.Platform%3DAndroid&hl=en). The outer phone and screen surfaces are currently square in a reversible border-radius trial; the Google search field and sign-in affordance retain their source-specific rounding. Typecheck passes; runtime visual comparison remains unverified because no browser probe was run.
