# Desktop / 0915 / 2 — moving, accumulating native windows

Experimental. `/desktop/native-windows/2`. Baseline: `/desktop/native-windows/1`. Version-owned: settings and plan, runner score; continuous motion and the rest of the infrastructure are [shared](./1.md#shared-infrastructure).

question: when a readable window keeps moving and new native windows cover it, does the desktop become a contested field of attention rather than a sequence of app demonstrations?
mutation: replace isolated jumps with continuous, phase-offset motion; grow multiple browser windows with unequal sizes; vary attention events between bursts and lulls.
invariants: real Chrome/Terminal/Preview/Slack, manual start with frozen settings, stop, no message sending, no server startup, existing desktop and browser work preserved.
evidence: pure geometry/sequence checks and static checks; experiential acceptance and live motion quality remain unverified.

## Reference ledger and interpretation

| Source | Evidence | Consequence for this trial |
| --- | --- | --- |
| [Amy Alexander, Scream (2005)](https://amy-alexander.com/scream) — artist primary description | Human screaming activates a Windows utility that disturbs the interface; challenges software's assumption of calm, focused users. | Disturbance needs an initiating act and changing intensity. Manual launch is the current trigger; microphone response is not implemented or implied. |
| [JODI, My%Desktop (2002), MoMA](https://www.moma.org/collection/works/193145) — institutional record | Four-channel recording of artist-performed OS 9 operations, including rapidly opened overlapping windows. Apparent malfunction is human choreography. | Use actual window occlusion, persistence and interrupted reading. Do not claim autonomous AI, reproduce a fake error aesthetic, or label randomness as JODI's method. |
| [My%20Desktop OSX10.4, ICC](https://www.ntticc.or.jp/en/archive/works/my-20desktop-osx10-4/) — institutional record | Rapid duplication, window opening, alerts and cursor gestures are a performed desktop. | Motion must affect what remains readable/foregrounded, not merely ornament a stable display. |

Proposed experience (our interpretation, not a source claim): a newly legible page begins to drift; other real pages occupy its place; differently phased windows briefly gather then separate. Large windows take visual territory while narrow windows reveal fragments. Slowing and renewed bursts make persistence and interruption perceptible. The version tests this relation; it does not establish artistic success by running successfully.

Sine/cosine combinations provide continuity, seeded stochastic events provide unequal encounters, and an irregular intensity envelope changes the shared pace. This is stochastic choreography, not a claim of mathematical chaos or reasoning agents. No reference executables are downloaded/run.

## Budget

At most eight browser windows created per run (default five), plus one trial Terminal. Batch motion at a target eight updates/second, never overlapping native calls. Real application rendering may be slower. Existing user windows are not selected for geometry operations; created IDs are tracked. Closing a trial window is treated as withdrawal, not automatically reversed. Final windows remain; repeated runs accumulate unless manually closed. Controls describe which apps support movement. No audio/microphone, destructive operations, or arbitrary shell input.

## Implementation and limits

Controls freeze interval, event count, countdown, selected apps, seeded order, jitter, amplitude, period, size, aspect-ratio spread, size breathing, window count and birth probability when Start is clicked. The controller supplies its display's available width/height, so run it on the controlled Mac's intended display. Version-specific endpoint: `/api/desktop/0915/2`. Native execution tracks only newly created window IDs. Browser contents are bounded public Wikipedia, Hacker News, arXiv and GitHub pages. No local replica windows or reference executables.

Motion uses paired 125 ms samples in a single AppleScript batch. Apple event latency, window minimum sizes, macOS placement restrictions and real page loading can distort the intended trajectory/rhythm; no 8 Hz smoothness guarantee. The Preview adapter stages a copy under `/private/tmp` and opens it through LaunchServices; the preceding user's permission failure is still a pending native verification, not an established fix. Stop leaves windows for inspection. The server's shared in-process child slot prevents simultaneous version launches; its state may be visible from either controller. No long-lived service is installed.

Checks: Goldfishes typecheck and 13 combined v1/v2 pure/admission tests passed. They cover settings snapshots, seeded events, bounds on three display sizes, motion continuity, rejected settings and origin restrictions. v1 settings, runner and CSS were byte-compared against the pre-fork flat baseline. The native v2 sequence has not been launched or visually validated; prior browser inspection hit a certificate interstitial, which was not bypassed. Artistic value remains the question to test, not a result asserted by these checks.
